# 六个开源 AI 短漫剧系统学习文档

本文是面向“AI 英歌漫剧生产工作台”的学习资料。目标不是抄代码，而是理解这些项目背后的生产系统设计思想、提示词组织方式、资产链路和可迁移能力。

## 0. 我们学习这些项目时要看什么

AI 漫剧/短剧系统有三个层次：

1. 工具层：能不能生图、生视频、配音、合成。
2. 生产层：剧本、角色、场景、分镜、关键帧、视频能否形成稳定流水线。
3. 资产层：每次生成是否沉淀为可复用资产，而不是一次性抽卡。

我们当前项目更关心第 2、3 层。

## 1. LumenX：SOP 流水线最值得学

项目地址：https://github.com/alibaba/lumenx

### 1.1 核心定位

LumenX 是阿里开源的 AI 短漫剧一站式生产平台。它的 README 明确提出完整 SOP：

```text
资产提取 → 风格定调 → 资产生成 → 分镜脚本构造 → 分镜图生成 → 分镜视频生成
```

这点很重要。它不是从“生成视频”开始，而是从资产提取和风格定调开始。

### 1.2 优点

#### 优点一：资产先行

LumenX 先从剧本里提取角色、场景、道具，再生成资产图。这样后续分镜不是凭空写 prompt，而是围绕已有资产进行组合。

对我们系统的启发：

- 角色中心、参考图库、全局风格模板库是正确方向。
- 关键帧生成时必须读取已采纳角色资产，而不是只读角色文字设定。

#### 优点二：角色一致性路径清晰

LumenX 对角色资产的流程大致是：

```text
角色文本描述
  ↓
无背景全身图
  ↓
三视图 / 头像特写
  ↓
后续服装、形态二次编辑
```

对我们系统的启发：

- 我们已有脸谱单图和真人妆照四面。
- 下一步角色生图应该先做“四视图/三视图”和“风格转换”。
- 生成结果不要直接覆盖参考图，要进入生成资产区。

#### 优点三：分镜阶段绑定资产

LumenX 分镜图生成时，每个分镜可以选择参与的角色、场景、道具作为参考图。

对我们系统的启发：

- 分镜卡字段里需要明确绑定角色资产、场景资产、道具资产、风格模板。
- 关键帧生成不能只靠自然语言，要靠资产引用。

#### 优点四：视频阶段支持抽卡选择

LumenX 的视频阶段支持多 batch 生成，最后选一个最佳版本进入合成。

对我们系统的启发：

- `GenerateTask` 要支持多输出结果。
- 输出结果应支持“设为最佳版本”。
- 视频片段也应该像图片一样有版本管理。

### 1.3 可迁移设计

迁移到我们系统：

```text
角色参考图库
  ↓
角色生图任务
  ↓
生成资产区
  ↓
人工采纳
  ↓
分镜关键帧
  ↓
视频片段多版本
  ↓
最终成片选择
```

## 2. Toonflow-app：Agent 分层和质量门最值得学

项目地址：https://github.com/HBAI-Ltd/Toonflow-app

### 2.1 核心定位

Toonflow 是一个偏 Agent 化的漫画/分镜生产系统。它的 `data/skills` 很值得看，里面把生产过程拆成：

```text
决策层 Agent
执行层 Agent
监督层 Agent
```

并定义了六阶段生产流水线：

```text
阶段1 衍生资产分析
阶段2 衍生资产生成
阶段3 导演规划
阶段4 构建分镜表
阶段5 分镜面板写入
阶段6 分镜图生成
```

### 2.2 设计思想

#### 思想一：决策层不直接执行

Toonflow 的决策层只负责理解用户意图、拆任务、调度执行层和监督层，不直接读写资产。

对我们系统的启发：

- 后续如果做 Agent，不要让一个 Agent 什么都干。
- 可以先不做多 Agent，但模块职责要像 Agent 一样清晰：
  - 剧本模块管故事。
  - 分镜模块管镜头。
  - 角色模块管角色资产。
  - 生成中心管任务执行。
  - 素材库管归档。

#### 思想二：阶段按顺序推进

Toonflow 要求阶段必须顺序执行，不能跳过关键前置条件。

对我们系统的启发：

- 关键帧生成前，要检查角色资产和风格模板是否准备好。
- 生视频前，要检查关键帧是否存在。
- 成片前，要检查视频片段是否选定最佳版本。

#### 思想三：监督层只提问题，不替用户决定

Toonflow 的监督层只做审核报告，修改决策权归用户。

对我们系统的启发：

- 我们应坚持“半自动优先于全自动”。
- AI 可以检查分镜、关键帧、prompt，但最终采纳由你决定。

### 2.3 分镜质量红线

Toonflow 的分镜表审核很专业，值得迁移。它强调：

- 内容忠实剧本。
- 台词原文锁定。
- 资产关联正确。
- 角色出现即引用。
- 场景资产必选。
- 视觉连续性。
- 朝向连续。
- 台词和时长强关联。
- 黄金 6 秒。
- 光影风格一致。

对我们系统的启发：

我们的分镜卡未来不只是“描述”，应该有校验规则：

```text
分镜卡 = 生产单元 + 质量检查对象
```

### 2.4 可迁移设计

短期迁移：

- 在分镜生成后加人工 checklist。
- 在关键帧采纳前加一致性检查。

中期迁移：

- 做轻量监督 Agent，检查导演规划、分镜表、关键帧。

## 3. LocalMiniDrama：生产体验和断点补全最值得学

项目地址：https://github.com/xuanyustudio/LocalMiniDrama

### 3.1 核心定位

LocalMiniDrama 是本地短剧助手，主打下载即用、本地运行、数据不上云。它的生产体验设计非常值得学。

### 3.2 优点

#### 优点一：一键生成 + 补全并生成

它不仅有“一键生成视频”，还有“补全并生成”：已有内容跳过，只生成缺失部分。

对我们系统的启发：

- 角色任务流要支持断点补全。
- 比如四视图已有正面、背面，缺半侧身，就只补缺失图。
- 分镜关键帧缺几张，就只补几张。

#### 优点二：失败重试

LocalMiniDrama 强调每步最多重试，应对 429 限流等错误。

对我们系统的启发：

- `GenerateTask` 不能失败就消失。
- 要保留输入、错误、重试入口。
- 重试要创建新任务，并关联旧任务。

#### 优点三：实时进度和错误日志

它显示当前步骤和完整错误日志。

对我们系统的启发：

- 生图工作台不能只显示“生成中”。
- 要显示：
  - 正在组装 prompt
  - 正在调用模型
  - 正在上传结果
  - 正在写入资产
  - 完成或失败

#### 优点四：全能分镜模式

LocalMiniDrama 有经典模式和全能模式。全能模式支持片段描述和 `@图片1`、`@图片2` 多参考图绑定。

对我们系统的启发：

- 生视频提示词不应只是一段文字。
- 对 Seedance / Omni 类模型，应该支持多参考图顺序：

```text
@图片1 = 场景图
@图片2 = 角色图
@图片3 = 道具图
@图片4 = 关键帧
```

### 3.3 可迁移设计

短期迁移到角色生图任务：

```text
任务状态 + step + 失败日志 + 重试
```

中期迁移到关键帧：

```text
补全缺失关键帧
只重试失败分镜
按分镜资产状态继续生成
```

## 4. huobao-drama：Skill 文件化和提示词规范最值得学

项目地址：https://github.com/chatfire-AI/huobao-drama

### 4.1 核心定位

huobao-drama 把短剧生产拆成多个 Skill：

- script_rewriter
- extractor
- storyboard_breaker
- voice_assigner
- grid_prompt_generator

这很像我们未来应该做的 `PromptTemplate / SkillTemplate`。

### 4.2 剧本改写提示词思想

它的剧本改写原则：

1. 保留核心情节。
2. 增强画面感。
3. 对话驱动。
4. 每场戏控制在 30-60 秒。
5. 不写镜头语言，因为镜头语言属于分镜步骤。

这个边界很重要。

对我们系统的启发：

- 剧本模块只负责故事和场次，不要过早塞景别、运镜。
- 分镜模块才负责镜头语言。

### 4.3 分镜拆解提示词思想

它的分镜字段包括：

- 标题
- 时间
- 地点
- 景别
- 角度
- 运镜
- 动作
- 对话
- 画面结果
- 氛围
- 时长
- image_prompt
- video_prompt
- bgm_prompt
- sound_effect
- scene_id
- character_ids

尤其重要的是 video_prompt 按时间段写：

```text
0-3秒：...
3-6秒：...
6-9秒：...
```

对我们系统的启发：

- 生视频提示词应该分段，而不是一整段。
- 每个分镜卡未来可以增加：
  - bgm_prompt
  - sound_effect_prompt
  - video_prompt_segments

### 4.4 宫格图提示词思想

huobao-drama 的宫格图提示词强调：

- exactly N visible panels
- no merged panels
- no missing panels
- consistent art style
- rows x cols grid layout

对我们系统的启发：

如果后续我们做“分镜宫格图预览”或“一次生成多张关键帧”，必须写清：

```text
exactly 4 visible panels
no merged panels
no missing panels
consistent art style
```

否则模型容易漏格、合格、乱格。

### 4.5 可迁移设计

我们应新增模板资产：

- 剧本生成模板
- 角色提取模板
- 分镜拆解模板
- 角色四视图模板
- 风格转换模板
- 关键帧模板
- 生视频分段模板
- 宫格图模板

## 5. waoowaoo：Prompt 资产分区最值得学

项目地址：https://github.com/saturndec/waoowaoo

### 5.1 核心观察

waoowaoo 里有大量 `lib/prompts` 文件，并且按能力分区：

- character-reference
- novel-promotion
- skills

它不是把 prompt 散落在业务函数里，而是作为可维护资产组织。

### 5.2 值得学习的提示词思想

#### 角色参考图转设定

它有类似：

```text
Analyze the provided character image and write one detailed English visual description for image generation.
```

以及：

```text
Use reference images only to preserve character identity traits (face, hairstyle, body shape, outfit structure), and do not let reference style override the requested style.
```

这句话非常适合我们。

对我们系统的启发：

- 角色参考图只用来锁身份和服饰结构。
- 风格由全局风格模板决定。
- 不能让参考图的拍摄风格覆盖目标漫剧风格。

#### 道具抽取规则

它对道具的定义很严格：只有跨场景、可携带、可复用的物件才算道具。普通桌椅、场景固定设施不算道具。

对我们系统的启发：

- 英歌角色的槌、蛇、鼓、旗等可以算角色道具。
- 场景里的普通装饰不要乱入道具库。
- 道具资产要服务跨分镜复用。

#### 场景稳定锚点

它要求场景生成可站位锚点 `available_slots`，用于后续角色放置。

对我们系统的启发：

- 场景资产不只是一张背景图。
- 应该带“可站位区域”：
  - 祠堂门口中央
  - 鼓阵左侧
  - 巷口石阶旁
  - 舞台前景右侧

后续关键帧生成时，角色位置更稳定。

### 5.3 可迁移设计

建议我们后面做 `PromptTemplate` 时，字段包括：

```text
模板名称
模块
模型兼容性
输入变量
输出 JSON Schema
模板正文
负面约束
版本
测试样例
```

## 6. FastMovieAI：平台化外围能力最值得学

项目地址：https://github.com/xhadmincn/FastMovieAI

### 6.1 核心定位

FastMovieAI 更像商用 SaaS/平台系统，包含用户、支付、积分、插件、WebSocket 等外围能力。

### 6.2 对我们有用的点

#### WebSocket / 推送

它使用 WebSocket 相关能力做平台实时交互。

对我们系统的启发：

- 生成任务进度适合用 SSE 或 WebSocket 推送。
- MVP 可以先用轮询，后续改 SSE。

#### 插件化

它有插件架构。

对我们系统的启发：

- 模型配置未来可以插件化：
  - Seedream provider
  - nano banana provider
  - gpt-image provider
  - video provider

但 MVP 不要过早做插件市场。

### 6.3 不建议迁移的点

暂时不迁移：

- 支付
- 积分
- 多租户
- 会员
- 小程序

这些会偏离内部生产工作台目标。

## 7. 对我们系统的统一迁移方案

### 7.1 架构原则

我们应该坚持：

```text
资产先行
任务驱动
人工采纳
质量门检查
Prompt 模板化
```

### 7.2 当前阶段最应该做什么

下一步不是直接接模型，而是做：

```text
角色生图任务流 MVP
```

原因：

- 参考图库已经有了。
- 风格模板库已经有了。
- 生成资产区已经有了。
- 缺的是“从输入到输出”的任务骨架。

### 7.3 推荐第一版任务类型

第一版只做：

1. 角色四视图生成。
2. 真人妆照风格转换。

不做：

- 表情表
- 动作姿态
- 武器道具
- 关键帧测试

这些后续加。

### 7.4 推荐任务结构

```text
GenerateTask
  - 角色
  - 生成类型
  - 模型
  - 参考图
  - 风格模板
  - prompt
  - negative prompt
  - params
  - input snapshot
  - status
  - step
  - progress
  - outputs
  - error
  - retry relation
```

### 7.5 推荐提示词系统

短期：

- prompt 可以先写在代码配置里，但要结构化。

中期：

- 做 PromptTemplate 管理。
- 所有 prompt 版本化。
- 每次任务记录 prompt 版本。

长期：

- 做 SkillTemplate，像 huobao-drama 和 Toonflow 一样，把不同生产能力封装为可维护技能。

## 8. 适合我们英歌题材的特别补充

这些开源系统多数偏通用短剧/漫剧，我们需要加入英歌特色：

### 8.1 英歌角色资产

角色资产重点不只是脸：

- 脸谱
- 头饰
- 服饰纹样
- 蛇/槌/鼓/旗等道具
- 身段动作
- 队列位置
- 角色气质

### 8.2 英歌动作资产

建议后续单独做：

```text
动作资产库
```

例如：

- 踏步
- 挥槌
- 转身
- 亮相
- 对打
- 队列行进

这些会强烈影响视频生成质量。

### 8.3 英歌场景资产

场景不只是背景：

- 祠堂
- 巷口
- 广场
- 舞台
- 鼓阵
- 巡游街巷

每个场景最好有：

- 背景图
- 可站位锚点
- 光影风格
- 人群密度
- 地面材质
- 文化元素

## 9. 最后结论

这 6 个项目给我们的最大启发：

1. LumenX 证明：AI 漫剧系统要有完整 SOP。
2. Toonflow 证明：复杂生成链路需要阶段和质量门。
3. LocalMiniDrama 证明：真实生产必须支持补全、重试、进度和错误日志。
4. huobao-drama 证明：提示词应 Skill 化，分镜字段要服务图片、视频、声音。
5. waoowaoo 证明：Prompt 是资产，应分区、版本化、测试化。
6. FastMovieAI 证明：平台化能力后期有价值，但 MVP 不应被支付/用户/积分牵走。

对我们当前系统来说，最重要下一步是：

```text
把角色生图任务流做成可追溯、可重试、可进入生成资产区的生产骨架。
```
