# AI Video Studio Development Workflow

更新时间：2026-05-08

## 1. 线程职责

本项目采用“指挥官线程 + 功能开发线程”的协作方式。

### 1.1 指挥官线程

指挥官线程负责项目总控，不直接承担长期功能开发。

职责：

- 维护项目当前状态和开发地图。
- 判断下一个最值得开发的模块。
- 为每个功能创建任务档案。
- 明确本次功能范围、验收标准和不做事项。
- 接收功能开发线程的完成记录。
- 更新项目总状态，并决定是否进入下一模块。

核心文档：

- `docs/current-development-map.md`
- `docs/development-workflow.md`
- `docs/features/*.md`
- `docs/decisions/*.md`

### 1.2 功能开发线程

功能开发线程只负责一个明确功能。

职责：

- 阅读对应的 `docs/features/<date>-<feature>.md`。
- 根据任务档案完成设计补充、开发、测试和自查。
- 和用户在该线程中完成体验验收。
- 功能完成后，在同一任务档案中补齐完成记录。
- 将完成记录带回指挥官线程。

功能开发线程完成后应关闭，不继续承接新模块。

## 2. 文档结构

```text
docs/current-development-map.md        # 项目总状态地图
docs/development-workflow.md           # 本协作流程
docs/features/<date>-<feature>.md      # 单功能任务档案
docs/decisions/<date>-<topic>.md       # 重大架构决策记录
```

## 3. 功能任务档案模板

每个功能开发前，指挥官线程创建一份任务档案。

```markdown
# 功能名称

状态：
负责人线程：
创建时间：
最后更新：

## 1. 为什么现在做

## 2. 目标链路

## 3. 本次范围

## 4. 明确不做

## 5. 涉及模块

## 6. 验收标准

## 7. 建议测试

## 8. 开发记录

## 9. 完成记录

## 10. 遗留问题

## 11. 下一步建议
```

## 4. 功能线程启动流程

1. 指挥官线程确认下一模块。
2. 指挥官线程创建或更新功能任务档案。
3. 用户开启新的功能开发线程。
4. 新线程第一条消息应包含任务档案路径。
5. 功能线程只围绕该任务档案工作。
6. 功能完成后，功能线程把完成记录写回任务档案。
7. 用户回到指挥官线程，指挥官线程更新开发地图。

推荐启动语：

```text
请读取 docs/features/<date>-<feature>.md，并按任务档案完成该功能的开发、测试和完成记录。
```

## 5. 完成记录格式

功能线程结束前必须写入：

- 完成了什么。
- 改了哪些文件。
- 怎么验证。
- 哪些测试通过。
- 哪些测试未能运行以及原因。
- 遗留问题。
- 是否建议进入下一阶段。

## 6. 更新规则

- `docs/current-development-map.md` 只记录项目总状态，不写过多过程细节。
- `docs/features/*.md` 记录单功能的完整过程和完成结果。
- `docs/decisions/*.md` 只记录影响后续多个模块的重大决策。
- 任务状态只使用：`planned`、`in_progress`、`reviewing`、`done`、`blocked`、`paused`。
