# 场景中心设计探索

状态：planned
负责人线程：待开启功能设计线程
创建时间：2026-05-09
最后更新：2026-05-09

## 1. 为什么考虑做

角色中心已经解决人物 IP、脸谱、参考图和角色生成一致性。接下来关键帧和视频生成会遇到另一个一致性问题：同一个祠堂、巷口、鼓阵广场、雨夜街道、舞台后台，在不同分镜和不同模型任务中容易长得不一样。

场景中心的目标是沉淀可复用的视觉场景资产，让后续模块可以引用同一个场景设定、参考图和场景 prompt。

## 2. 当前判断

现有 `scenes` 模块更接近“剧本场次”，不是“视觉场景资产”。

建议先区分两个概念：

- 剧本场次：故事结构单位，例如第 1 场、第 2 场。
- 场景中心：视觉资产单位，例如英歌祠堂、潮汕老街、鼓阵广场、夜雨巷口。

两者后续可以关联，但第一版不建议混成一个表。

## 3. 放在导航里的可能性

用户倾向在主导航中新增“场景中心”，与“角色中心”“风格模板”同级。

初步定位：

```text
角色中心：人物一致性
场景中心：空间一致性
风格模板：画风一致性
项目中心：把角色/场景/风格组织进具体项目
```

## 4. 三种可能方案

### 方案 A：全局场景中心

把场景中心做成全局资产库，类似角色中心。

优点：

- 场景可跨项目复用。
- 适合沉淀英歌题材常用空间，例如祠堂、巷口、鼓阵、舞台、村口、海边、训练场。
- 后续项目可以引用这些场景。

缺点：

- 第一版需要同时考虑全局库和项目引用。

### 方案 B：项目内场景库

只在项目详情里做“项目场景”文件夹。

优点：

- 更贴近当前项目生产。
- 实现更轻。
- 可以直接服务分镜和关键帧。

缺点：

- 跨项目复用弱。
- 未来可能要再抽全局场景中心。

### 方案 C：全局场景中心 + 项目引用，推荐方向

先承认场景是全局资产，但第一版只做最小可用链路：

```text
全局场景中心
  ↓
项目引用场景
  ↓
后续分镜卡绑定项目场景
  ↓
关键帧生成读取场景设定和参考图
```

优点：

- 和角色中心/项目角色的架构一致。
- 后续关键帧可以同时读项目角色和项目场景。
- 不容易返工。

缺点：

- 需要先设计好最小字段，避免一上来做重。

## 5. 新线程需要回答的问题

进入功能设计线程后，需要先用用户提供的 skill 辅助回答：

- 场景中心是全局模块、项目内模块，还是两层结构？
- 场景资产最小字段是什么？
- 场景是否需要参考图？
- 场景是否需要 AI 解析和 prompt draft？
- 场景和现有“风格模板/场景模板”的关系是什么？
- 场景和剧本 `Scene` 的关系是什么？
- 场景和道具是否一起做，还是先只做空间？
- 第一版是只做设计文档，还是直接实现基础 CRUD？

## 6. 暂定不做

在设计未定前，暂不做：

- 关键帧生成。
- 生视频生成。
- 自动从剧本抽取场景资产。
- 复杂空间关系图。
- 3D 场景或镜头调度。
- 场景资产自动评分。
- 大规模数据库迁移。

## 7. 建议第一版产物

建议新线程先产出设计结论，而不是直接写代码：

- 场景中心产品定位。
- 场景资产字段草案。
- 全局场景与项目场景引用关系。
- 与风格模板、剧本场次、分镜卡、关键帧生成的边界。
- MVP 实现范围。
- 后续开发任务档案。
